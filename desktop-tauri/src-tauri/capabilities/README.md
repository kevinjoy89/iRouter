# `capabilities/` 的两条来源（为什么这里只有一个 JSON 文件）

| 来源 | 作用域 | 位置 |
| :--- | :--- | :--- |
| `default.json`（本目录，静态） | **本地 origin**：窗口启动时先加载的兜底页 `dist/index.html`（`WebviewUrl::App`）。它不调任何 IPC，所以只给 `core:default` | 本目录 |
| 远端面板 capability（**动态**，不在本目录） | **远端 origin**：`http://127.0.0.1:<实际端口>` 的面板。`window.irouterShell` 的全部 IPC 都走这一条 | `desktop-tauri/src-tauri/src/main.rs`（Lead 持有）里的 `Manager::add_capability` |

## 1. 为什么不能写成一个 JSON 文件

网关端口是**每次启动自适应**的：`desktop/main.js:151-159` 的 `pickPort` 先扫 `20128..20178`（`DEFAULT_PORT + PORT_SCAN_SPAN`），全被占用时**回落 `srv.listen(0)` 的 OS 临时端口**——端口无上界。

于是静态 capability 只有两种写法，都不可接受：

- `"remote": { "urls": ["http://127.0.0.1:20128"] }`：端口一旦漂移，面板的 `invoke` 全部被 ACL 拒（`authority.rs` 的 `resolve_access` 返回 `None`）。**这个拒绝不会报错到面板 UI**——`checker.js:161-165` 只在命中时填 `assetName`，面板表现为「软件更新」整段消失或永远没有产物，排查成本极高。
- 通配端口（`http://127.0.0.1:*/`）：免维护，但把 ACL 边界放宽到**任何**本地端口。面板是本机唯一内容源，没有收益，不采纳。

因此按**实际端口**动态加（`dynamic-acl` **在 `tauri` 的默认 feature 里**，2.12.1 的 `crates/tauri/Cargo.toml` `default = ["wry","compression","common-controls-v6","dynamic-acl","x11","dbus"]`）。

## 2. 需要 Lead 在 `main.rs` 里接的线

在 `gateway::spawn` 拿到 `port` 之后、**窗口 `build()` 之前**加一条（必须用 `port` 变量，不要用常量）：

```rust
use tauri::ipc::CapabilityBuilder;
use tauri::Manager;

/// 面板是远端 origin，端口每次启动都可能变（pickPort 扫不到就回落 OS 临时端口）。
/// 静态 capability 写死端口 → 更新通道与设置读写被 ACL 静默拒绝，所以按实际端口动态加。
fn add_remote_panel_capability(app: &tauri::AppHandle, port: u16) -> tauri::Result<()> {
    app.add_capability(
        CapabilityBuilder::new("remote-panel")
            // 只对远端 origin 生效：不加的话这条 capability 会连带把 Local 也授出去
            // （resolved.rs:280 的 `if capability.local { contexts.push(Local) }`）。
            .local(false)
            .window("main")
            .remote(format!("http://127.0.0.1:{port}"))
            // ── 事件：4 个更新事件 + shell:open-settings 全由 Rust 侧 emit，面板只订阅 ──
            // （updater shim 的 unlisten 也要它；shell shim 目前只本地退订，留着不为过）
            .permission("core:event:allow-listen")
            .permission("core:event:allow-unlisten")
            // ── 更新器 5 条（命令名见 src/updater/commands.rs）──
            .permission("allow-shell-check-update")
            .permission("allow-shell-download-update")
            .permission("allow-shell-cancel-download")
            .permission("allow-shell-install-update")
            .permission("allow-shell-ignore-version")
            // ── shell 3 条（命令名见 src/shell/commands.rs）──
            .permission("allow-shell-get-settings")
            .permission("allow-shell-set-settings")
            .permission("allow-shell-context-menu")
    )
}
```

调用点（现有 `setup` 的骨架里）：

```rust
let gw = gateway::spawn(&handle, &panel_guard)?;
let port = gw.port;
add_remote_panel_capability(&handle, port)?;   // ← 在这一行之后才 build 窗口
```

`IROUTER_PANEL_URL` 开发捷径分支同理：把该分支里解析出的 URL 的端口也加一条（或直接复用同一个函数），否则 dev 下面板同样调不通 IPC。

> ✅ 前置条件已满足：`shell_context_menu` 已在 `7b34ddbf` 补进 `build.rs` 的
> `AppManifest::commands(&[...])`，生成物 `permissions/autogenerated/shell_context_menu.toml` 里的
> identifier 就是 `allow-shell-context-menu`。10 条权限逐一核对过生成物，可直接照用（见 §3 的对照表）。

### 依据（都锁定 tag `tauri-v2.12.1`）

- `Manager::add_capability(&self, capability: impl RuntimeCapability) -> tauri::Result<()>`：`crates/tauri/src/lib.rs#L840-L848`，`#[cfg(feature = "dynamic-acl")]`。
- `CapabilityBuilder::{new, local, window, remote, permission}`：`crates/tauri/src/ipc/capability_builder.rs#L19-L156`；`RuntimeCapability` 由 `crates/tauri/src/ipc/mod.rs#L38` re-export。
- `local` 默认 `true`、`remote` 默认 `None`：`crates/tauri-utils/src/acl/capability.rs#L110-L166`、`#L230`。
- `local` → `ExecutionContext::Local`，`remote.urls` → `ExecutionContext::Remote`，两者独立追加：`crates/tauri-utils/src/acl/resolved.rs#L277-L295`。
- 匹配发生在 IPC 请求的 `Origin` 上：`crates/tauri/src/ipc/authority.rs#L462-L479`。
- URLPattern 会补空 path/search/hash：`"http://127.0.0.1:20128"` 本身即可匹配该 origin 的任意路径（`tauri-utils` 的 `RemoteUrlPattern::from_str`）。

## 3. 权限清单的约束

1. **权限标识是 kebab-case，不是命令名的原样**：`tauri-utils/src/acl/build.rs` 生成的是
   `allow-{command.replace('_', "-")}`（`crates/tauri-utils/src/acl/build.rs#L289-L298`，可在本地
   `src-tauri/permissions/autogenerated/*.toml` 里逐字核对，例如 `shell_get_settings` 生成的是
   `allow-shell-get-settings`）。写成 `allow-shell_get_settings` 会**在启动时 panic**：
   `RuntimeAuthority::add_capability_inner` 里 `Resolved::resolve_with_base_scope_id(...).unwrap()`
   （`crates/tauri/src/ipc/authority.rs#L174-L180`），未知权限让 `resolve` 返回 `Err(UnknownPermission)`
   → `unwrap` 炸掉 → `setup` 失败。**响亮失败，不是静默**，但仍要一次写对。
2. **每个命令都必须先在 `src-tauri/build.rs` 的 `AppManifest::commands(&[...])` 里声明**。当前声明（8 个，与 `permissions/autogenerated/*.toml` 一一对应）：

   | 命令名（snake_case，`generate_handler!` / JS `invoke()` 用） | 权限 id（kebab-case，capability 里写这个） |
   | :--- | :--- |
   | `shell_check_update` | `allow-shell-check-update` |
   | `shell_download_update` | `allow-shell-download-update` |
   | `shell_cancel_download` | `allow-shell-cancel-download` |
   | `shell_install_update` | `allow-shell-install-update` |
   | `shell_ignore_version` | `allow-shell-ignore-version` |
   | `shell_get_settings` | `allow-shell-get-settings` |
   | `shell_set_settings` | `allow-shell-set-settings` |
   | `shell_context_menu` | `allow-shell-context-menu` |

   命令改名时，`build.rs` 与本文件 §2 的清单必须同时改。
3. **不要给远端 capability 加 `core:default`**：它会把 window / app / path / menu / tray 等一大片命令授给远端 origin，而更新通道一条都用不到。
4. **不要加 `shell:allow-execute` / `shell:allow-spawn`**：sidecar 由 Rust 侧 `app.shell().sidecar("irouter-bun")` 构造，**不经过 scope 校验**（`plugins-workspace` v2 `plugins/shell/src/lib.rs#L71-L73`），文档里那段给 JS 用的 `shell:allow-execute` 与本项目无关。IPC 面按 ADR-0007 压到最小。
5. **不要加 `opener:*`**：安装器由 Rust 侧 `tauri_plugin_opener::open_path` 调起，不走 webview→IPC。
6. **不要加 `core:window:*` / 托盘 / 菜单权限**：窗口显隐、关闭拦截、`TrayIcon`、`popup_menu_at` 全是 Rust 侧 API，capability 只管 webview→IPC。
7. 自定义命令**默认对所有窗口开放**，但**远端 origin 一定要显式列进 capability**：`tauri-2.12.1/src/webview/mod.rs` 注释原文——
   > Check ACL on plugin commands, when the app defined its ACL manifest, or when the request comes from a non-local (remote) origin. This ensures remote content can never reach custom commands unless an explicit `remote` capability has been configured for them.
8. 静态 capability 文件里的拼写错误会在**构建期**被 `tauri-build` 的 `validate_capabilities` 拦下（`crates/tauri-build/src/acl.rs`）；**动态**加的这一条没有这层保护，只能靠这里的清单与 `build.rs` 对齐。
9. 安全提示（官方 Capabilities 文档）：Linux / Android 上 Tauri **无法区分来自内嵌 `<iframe>` 的请求与窗口自身的请求**。面板若将来会嵌入第三方 iframe，这条 capability 的边界要重新评估。

## 4. 何时会失败、怎么看出来

- 端口漂移但 capability 没跟上：`invoke` 被拒，**面板不报错**，只是「软件更新」整段消失。排查看 stderr 里 Tauri 的 `resolve_access_message` 输出（会打印 `URL: <pattern>` 与命中/未命中的 capability）。
- 权限名拼错 / 漏声明 / 用了 snake_case：`add_capability` 直接 panic，**进程起不来**（fail-closed）。
- 命令没有登记进 `build.rs` 的 app manifest：`generate_allowed_commands` 不会把它放进允许清单，面板 invoke 得到 “Command not found”（也是我们要的 fail-closed，但要靠 CI 的包内冒烟早发现）。
