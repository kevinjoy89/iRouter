## Purpose

负责将模型测速与基准评测的历史指标持久化落入本地 SQLite 数据库，提供多维检索分析，并在敏感凭据安全脱敏的前提下支持数据导出与清理。

## ADDED Requirements

### Requirement: 测速指标结构化持久化
系统 SHALL 在每轮测速成功或异常中止时，将结构化评测指标持久化存储至 SQLite 数据库中的 `speedtest_results` 表。

#### Scenario: 成功写入完整测速轮次记录
- **WHEN** 一轮测速执行完毕并完成指标计算
- **THEN** 系统将 batch_id、模型、网关、TTFT、稳定速度、分位数指标与降采样曲线点写入 SQLite 数据库

### Requirement: 敏感 API 凭据全程安全脱敏
系统 SHALL 确保 API Key 等鉴权凭据仅在网络请求阶段内存使用，在任何持久化阶段均被脱敏或隔离。

#### Scenario: 数据库记录仅存脱敏指纹
- **WHEN** 记录被持久化或前端拉取历史记录
- **THEN** 数据库及接口仅返回脱敏后的 Key 指纹（前后各 5 位且中间打码），绝不包含完整原始密钥

### Requirement: 历史统计聚合与图表查询
系统 SHALL 支持按模型与网关主机聚合历史测速记录，为趋势折线图和速度梯队条形图提供高效查询支撑。

#### Scenario: 查询多模型速度梯队与 TTFT 历史趋势
- **WHEN** 仪表盘进入图表分析视图
- **THEN** 后端聚合返回各模型的中位数稳定吐词速度与随时间推进的 TTFT 走势序列

### Requirement: 历史数据导出与配额维护
系统 SHALL 支持将本地存储的历史评测数据导出为标准 JSONL 文件，并提供容量维护与清理机制。

#### Scenario: 一键导出基准评测历史为 JSONL
- **WHEN** 用户点击「导出 JSONL」操作
- **THEN** 系统将选定或全部历史记录格式化为单行 JSON 格式并触发文件下载

#### Scenario: 记录容量上限控制与手动清理
- **WHEN** 用户执行历史清空操作或本地记录超过预设阈值
- **THEN** 系统从数据库中清理目标记录，释放本地存储空间
