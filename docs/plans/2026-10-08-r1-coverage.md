### 1.1 一处**已知且有意保留**的行为差异

JS：`typeof [] === "object"` → **数组**会被当作合法 `lastCheckResult` 保留；
Rust：`Value::is_object()` 对数组为假 → 丢弃。

保留理由：① `lastCheckResult` 唯一写入方是更新器（写 `CheckResult` 对象），数组不可能出现；
② 丢弃非法形状比原样保留更安全。**若要严格等价需改 `src/settings.rs`（Lead 持有，本卡写域外）。**
已由 `shell::settings_contract::known_divergence_js_accepts_array_last_check_result_rust_drops_it`
**钉成显式差异**，避免日后误以为"已完全对齐"。

## 2. `desktop-shell-i18n.test.js`（5 个 case）→ Rust 对账

被测对象：`desktop/main.js` 内的 `MENU_TRANSLATIONS` + `getMenuI18n` → 已移植为 `src/shell/i18n.rs`。

**结论：Rust 侧保障**强于** JS 侧**——三份字典是同一个 `Strings` 结构体的三个实例，
"缺键 / 多余键"都是**编译错误**，不需要运行期测试。5 个 case 无一属于"覆盖丢失"。

| # | JS case | Rust 处置 | 依据 |
| --: | :--- | :--- | :--- |
| 1 | 解析到了语言字典（防止解析逻辑静默失效） | 随壳消失 | 该 case 是**测试自身解析器**的自检（从 JS 源码文本里正则抽对象字面量）。Rust 侧没有"解析源码"这一步，无对应物 |
| 2 | 每种语言不能有英文之外的意外多余键 | 随壳消失（**由类型系统代替**） | 三个 `static Strings` 同类型；多余/缺失键=编译错误。另有 `shell::i18n::tests::all_locales_expose_the_same_key_set` 把"三份键集合一致且为 39 个"钉成可执行证据 |
| 3 | 缺键由 `getMenuI18n` 以英文兜底合并 | `shell::i18n::tests::normalize_matches_electron_rules` | 语言级兜底仍在（非 zh → `Locale::En`）；"键级兜底"在 Rust 里不存在也**不需要**（缺键编译不过） |
| 4 | 中文三种语言齐全地译了 `settings` | `shell::i18n::tests::every_locale_has_non_empty_labels`（**升级**） | 由"抽样 3 个键"升级为**遍历全部 39 键 × 3 语言** |
| 5 | zh-CN / zh-TW 的 `settings` 确实译成了中文 | `shell::i18n::tests::chinese_locales_are_actually_translated`（**新增**）+ `english_locale_has_no_cjk`（**新增**） | 由"只查一个键"升级为**遍历 39 键**；并加了反向守卫（英文槽里不得出现中文） |
