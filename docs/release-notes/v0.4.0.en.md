# iRouter v0.4.0 Release Notes

[简体中文 (Chinese Version)](v0.4.0.zh-CN.md) | [GitHub Release Page](https://github.com/kevinjoy89/iRouter/releases/tag/v0.4.0)

> **iRouter** is a cross-platform desktop application for the LLM router gateway based on [decolua/9router](https://github.com/decolua/9router).
> **v0.4.0 replaces the desktop shell**: the heavyweight Electron shell is gone, replaced by **Tauri v2 (Rust) + a Bun sidecar**.
> The macOS installer drops from **139.65 MiB to 46.5 MiB** (−66.6%) with **every feature preserved**, including in-app updates.
> The gateway source is untouched and keeps its merge lineage with upstream.

---

### 🎯 The core change: a new shell

#### 1. Shell: Electron → Tauri v2 (Rust)

The old shell bundled a full Chromium (`Electron Framework` alone was 192 MiB). The new shell uses **Tauri v2**:
rendering is delegated to the **system webview** (WKWebView on macOS, WebView2 on Windows, WebKitGTK on Linux),
and the shell itself becomes a few-MiB Rust binary.

#### 2. Gateway runtime: Electron's bundled Node → a shipped Bun sidecar

Previously the gateway reused Electron's Node. Now **Bun ships as a sidecar** with its hashes pinned in-tree
(`tools/bun-pin.json`, five platforms). This is what makes the size math work: choosing Node SEA instead would
only reach ~79 MB for the same shell swap — past the 70 MB line we set for ourselves.

#### 3. Size comparison (measured, not estimated)

| | Electron (v0.3.7) | **Tauri + Bun (v0.4.0)** |
| :--- | ---: | ---: |
| macOS (Apple Silicon) dmg | **139.65 MiB** | **46.5 MiB** |
| Installed size | ~324 MiB | ~150–180 MiB range |

### ✅ Feature parity (nothing dropped)

Swapping the shell is not an excuse to drop features. All of the following were re-implemented and verified:

- **Window & panel**: waits for gateway readiness before showing (no white flash); panel guard token blocks direct browser access
- **System tray**: left-click, context menu, double-click, tooltip; template icon adapts to light/dark menu bar
- **Native menus**: macOS app menu (including Edit — Cmd+C/V/X/A depends on it) and Help menu
- **Close behavior**: all three `closeAction` modes (quit / dock / tray), wired to the settings panel
- **Launch at login**: two-way synced with the actual system state
- **Single instance**: a second launch surfaces the existing window instead of starting another gateway
- **In-app updates**: check / download (with progress and cancel) / verify / hand off to the installer — **byte-for-byte the same behavior as 0.3.x**
- **Native dialogs**: results and failures of "Check for Updates"
- **Localization**: menus and dialogs in en / zh-CN / zh-TW

#### Orphan processes (the easiest thing to break in a shell swap)

The gateway is a child process — **if the shell dies, the gateway must not survive**, or it keeps holding
`127.0.0.1:20128`. Three death paths are handled, each backed by real-machine measurements:

| Path | Behavior |
| :--- | :--- |
| Normal exit (tray "Quit" / menu Quit) | Reaps the gateway **process tree**, clears the PID file |
| `SIGTERM` / `SIGINT` | Same reaping path (matches the Electron implementation's signal handling) |
| Close window to tray (dock mode) | Gateway keeps serving — intended |
| **Orphan left by a previous crash** | **Reaped on next launch via the PID file**; the port is never permanently held |

### 📦 Upgrading

**On 0.3.x? Just use "Check for Updates" in the app** — no manual download needed.

Asset names are kept **byte-for-byte identical** to 0.3.x (`iRouter-<version>-<platform>-<arch>.<ext>`).
That is deliberate: the old client matches asset names by **exact string equality**, so renaming would cut off
every existing user's update path. Three layers of assertions in the repo guard this rule.

After upgrading you get a **brand-new application** (the shell changed), so macOS may ask you to confirm once.

---

### ⚠️ Known limitations

- **First-launch system prompt**: installers are ad-hoc signed (no paid developer certificate). On macOS the
  first launch needs a right-click → Open, or a one-time allow in System Settings → Privacy & Security.
- **Windows / Linux were not verified on real machines**: CI builds all four platforms and runs in-package smoke
  checks every round (sidecar present, gateway payload present, minimum OS version correct), but **nothing was
  installed and run by hand**. The macOS manual pass caught a defect CI could never see (the tray icon rendered
  as a blank square), so please report anything similar on other platforms.
- **macOS 13.0 minimum**: that is a requirement of the shipped Bun binary itself, not our choice.
- The Linux `.deb` declares `webkit2gtk` (the system webview Tauri requires).

### 🔧 Technical details

- **Decision records**: [ADR-0007](https://github.com/kevinjoy89/iRouter/blob/main/docs/adr/0007-tauri-bun-shell.md)
  (the shell swap), ADR-0001 (now superseded, with a factual correction), ADR-0004 (version decoupling — the
  source of truth moved to `desktop-tauri/package.json` in this migration)
- **Full migration record**: [docs/plans/2026-10-07-tauri-bun-migration.md](https://github.com/kevinjoy89/iRouter/blob/main/docs/plans/2026-10-07-tauri-bun-migration.md)
  — size budget, per-phase verification for Phases 0–6, real death-path table, risks and rollback
- **Repo layout**: `desktop-tauri/` (shell), `tools/` (load-bearing build inputs: gateway payload build,
  Bun pin/verification, artifact naming source of truth), `build/` (payload output). The old `desktop/`
  (Electron shell) has been removed
- **Automation seams**: `npm run verify:guard` / `verify:shell` / `verify:updater-shim` — three re-runnable
  gates, each with a **negative verification** (deliberately break an assertion and confirm it actually goes red)
