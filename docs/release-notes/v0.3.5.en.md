# iRouter v0.3.5 Release Notes

[简体中文版](https://github.com/kevinjoy89/iRouter/blob/main/docs/release-notes/v0.3.5.zh-CN.md) | [GitHub Release](https://github.com/kevinjoy89/iRouter/releases/tag/v0.3.5)

> **iRouter** is a cross-platform desktop client for a large-model routing gateway, deeply customized from [decolua/9router](https://github.com/decolua/9router). This is a bug-fix release on top of v0.3.4: it fills in the settings-panel strings that were missing translations, and fixes a crash that blanked the whole panel.

---

### 🛠️ Fixes

#### 1. Missing translations in the settings panel (e.g. "Downloading update...")
- **Symptom**: while downloading an update, the settings panel showed the English string `Downloading update...` under every locale.
- **Cause**: the text was a hard-coded JSX node with **no entry in the runtime i18n dictionary** (the runtime translates by exact match, so a missing entry is shown verbatim in English).
- **Fix**: the whole settings panel was swept for the same class of gap. Besides `Downloading update...`, two more were found — the observability save-failure notice and the shell-settings loading placeholder — and all are now in the dictionaries (Simplified and Traditional Chinese).
- **Hardening**: the dictionary-coverage guard only recognised JSX text **wrapped in newlines**, so same-line button/status labels escaped it entirely — which is exactly how this gap appeared. A same-line extraction rule was added and verified by mutation testing (deleting the entry makes the guard fail immediately).

#### 2. Blank panel when landing on the Window / Software Update sections
- **Symptom**: opening the settings panel directly on the "Window" or "Software Update" section (or switching to it while the shell settings were still loading) blanked the entire panel.
- **Cause**: those two sections read asynchronously loaded shell settings, but the content branch — unlike the left-hand nav — did not check whether they had arrived yet, so it passed `null` down.
- **Fix**: rendering now uses the same readiness check as the nav and shows a placeholder instead of crashing.

---

### 🧰 Engineering

- **Release pipeline automation**: pushing a tag now publishes the GitHub Release with its **title and release notes filled in automatically** (the notes are read from `docs/release-notes/v<version>.zh-CN.md`). Previously the body had to be written by hand after publishing — both v0.3.3 and v0.3.4 were patched that way. A missing notes file now fails the pipeline instead of producing an empty release.
- **CI gate stability**: the `usage-dispatch` test dynamically loads a large module graph, which under parallel execution could exceed the default timeout and be misreported as a regression; it now has an explicit timeout.

---

### 💎 Local-Only Core Capabilities Fully Retained

Smart retry & backoff (`retryCfg`), outbound data redaction (DLP), thinking-effort clamping (`effortCap`) and Combo cross-model 4xx failover are all unchanged.

> **macOS Gatekeeper Notice**:
> Since this is a personal open-source application without an Apple paid developer certificate (unsigned and un-notarized), macOS Gatekeeper may show a warning upon first launch. You can bypass it by:
> 1. In Finder -> Applications, **Right-click (or Control-click) iRouter -> Open -> click Open** in the prompt;
> 2. Or go to System Settings -> Privacy & Security -> Security, find the blocked entry and click "Open Anyway".
> This confirmation is only needed once on first launch; double-clicking works afterwards.
